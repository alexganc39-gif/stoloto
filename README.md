\# «Воздушный Шар» — бонусная crash-игра



> \*\*Дисклеймер.\*\* Игра создана как прототип для чемпионата. Все операции

> имитационные: реальных денег, ставок и финансовых рисков нет. Бонусные

> баллы, игровые очки, билеты и турнирные места не имеют денежной стоимости.



Прототип бонусной crash-игры для «Столото»: игрок ставит бонусные баллы,

наблюдает за растущим коэффициентом и должен нажать «Забрать» до того, как

шар лопнет. Решение включает выбор темы, бустеры, живой рейтинг, турнирную

таблицу и апсейл лотерейных билетов.

\## Стек технологий



| Слой | Технология | Обоснование |

|---|---|---|

| Backend | Java 17+ (JDK) + `com.sun.net.httpserver.HttpServer` | Требование брифа: «Backend: Java». Встроенный HTTP-сервер из JDK — нулевые внешние зависимости, работает без Maven и Gradle |

| Frontend | Vanilla HTML + CSS + JavaScript | Требование брифа: «любой современный фреймворк или ванильный JS». Без сборщиков — проще запускать и проверять |

| Real-time | Polling каждые 150 мс | Бриф допускает polling ≤ 1 сек. Реализовано через `setInterval` |

| Хранилище | In-memory `ConcurrentHashMap` | Достаточно для прототипа; в разделе «Масштабирование» описано, как перейти на PostgreSQL |

| Конфигурация | `config.properties` + админ-панель | Горячая перезагрузка без перекомпиляции (Сценарий 5) |



Внешних зависимостей нет — только JDK. Запуск одной командой: `javac \*.java \&\& java Main`.

\## Математическая модель



\### Рост коэффициента



```

multiplier(t) = e^(growthRate · t)

```



где `t` — секунды с начала раунда, `growthRate` — настраиваемый параметр (по умолчанию 0.18). При значении 0.18 коэффициент растёт примерно ×1.2 в секунду.



\### Точка краха



```

crash = clamp( (1 − houseEdge) / (1 − r), minCrash, maxMultiplier )

```



где `r = uniform(0, 1)`. Это классическое распределение crash-игр: медиана при `houseEdge = 0.03` составляет ≈ \*\*1.95×\*\*, что даёт дому статистическое преимущество около 3%.



Значения параметров: `houseEdge = 0.03`, `minCrash = 1.00`, `maxMultiplier = 50.0`.



\### Уровни



Порог уровня `i` — `(1 + levelStep)^i`. При `levelStep = 0.15`:



\- Уровень 1: ×1.15

\- Уровень 2: ×1.32

\- Уровень 3: ×1.52

\- …

\- Уровень 12: ×5.35 (красная тема)

\- Уровень 9: ×3.52 (зелёная тема)



Уровень 1 достигается примерно за 0.8 сек, поэтому кнопка «Забрать» становится активной практически сразу — как и требует бриф.



\### Бустер



Если выбран бустер ×N, сервер \*\*до старта раунда\*\* выбирает случайный уровень в диапазоне от 2 до `totalLevels − 1`. При достижении этого уровня текущий коэффициент умножается на значение бустера и продолжает расти от новой базы.



Пример: без бустера к 6-й секунде коэффициент ×2.94. С бустером ×3 на 4-м уровне (порог ×1.52, достигается на \~2.3 сек) коэффициент после активации становится `1.52 × 3 = 4.56` и продолжает расти от этой величины.



\### Очки



\- `points.per.line` (по умолчанию 10) — за каждый пройденный уровень

\- `points.booster.bonus` (25) — при активации бустера

\- `points.cashout.bonus` (15) — за успешный cashout



Очки начисляются и при выигрыше, и при проигрыше.



\### Честность (provably fair)



При создании раунда сервер генерирует `serverSeed` и сразу отправляет клиенту `commitHash = SHA-256(serverSeed + ":" + crashMultiplierStr)`. До старта раунда клиент имеет только хеш и не имеет seed — следовательно, не может предсказать исход.



После завершения раунда сервер раскрывает `serverSeed` и `crashMultiplierStr`. Клиент пересчитывает SHA-256 и сверяет с хешем, полученным \*\*до\*\* старта. Совпадение доказывает, что сервер не подменил результат.



Клиентская проверка реализована на экране результата, в раскрывающемся блоке «Проверка честности».



\*\*Важно:\*\* хеш вычисляется от точной строки, которую Java генерирует из `double` (например, `"50.0"`, а не `"50"`). Поэтому сервер дополнительно отправляет клиенту `crashMultiplierStr` — точное строковое представление, чтобы браузерный `SHA-256` использовал идентичные байты.

\## Конфигурация



Все параметры находятся в `backend/config.properties` и читаются заново при создании каждого нового раунда. Уже идущий раунд использует снимок значений, снятый в момент ставки.



| Параметр | Допустимый диапазон | Назначение |

|---|---|---|

| `growth.rate` | 0.05 – 0.5 | Скорость роста коэффициента |

| `min.crash.multiplier` | ≥ 1.00 | Нижняя граница краха |

| `max.multiplier` | > `min.crash.multiplier` | Верхняя граница краха |

| `level.step` | 0.05 – 0.5 | Шаг между уровнями |

| `levels.red` / `levels.green` | целое > 0 | Количество уровней в теме |

| `points.booster.bonus` | целое ≥ 0 | Очки за активацию бустера |

| `points.cashout.bonus` | целое ≥ 0 | Очки за успешный cashout |

| `demo.starting.balance` | ≥ 0 | Стартовый баланс демо-пользователя |

| `popup.timeout.seconds` | > 0 | Таймаут автозакрытия апсейла |



Валидация значений выполняется на клиенте, в форме «⚙ Настройки». Некорректное значение отклоняется с сообщением об ошибке; запрос на сервер не отправляется.

\## Известные ограничения



\- \*\*Хранилище в памяти.\*\* Состояние живёт в JVM и сбрасывается при перезапуске. Для production необходима СУБД (PostgreSQL) — модель данных уже вынесена в отдельные классы.

\- \*\*Polling вместо WebSocket.\*\* Интервал 150 мс, приемлемо для одного пользователя. При большом числе одновременных клиентов потребуется WebSocket/STOMP.

\- \*\*Имитация рейтинга и турнира.\*\* «Другие игроки» — фиксированный вымышленный пул в `Tournament.java`, а не реальные аккаунты.

\- \*\*Один демо-пользователь.\*\* `USER\_ID = "demo"` задан в коде, авторизация отсутствует.

\- \*\*Админка — форма, а не полноценный CRUD.\*\* Нет разграничения прав, ролей и журнала изменений.

\- \*\*Упрощённая схема честности.\*\* Клиент сверяет SHA-256 после раунда, но seed генерирует сервер. Полноценная реализация provably fair требует, чтобы клиент также передавал свой seed.



\## Возможности масштабирования



1\. \*\*Backend на Spring Boot + WebSocket\*\* вместо HttpServer и polling. Классы `GameMath`, `Store`, `Config` переносятся почти без изменений — они не завязаны на HTTP-слой.

2\. \*\*PostgreSQL вместо in-memory.\*\* Таблицы `users`, `rounds`, `configs`. Классы `User` и `Round` — чистые модели.

3\. \*\*Полноценный provably fair.\*\* Клиент передаёт собственный seed, сервер комбинирует его с serverSeed.

4\. \*\*Интеграция с платёжными системами и реальными ставками.\*\*

5\. \*\*ML для персонализации ставок.\*\* Логирование поведения пользователей → рекомендации.
